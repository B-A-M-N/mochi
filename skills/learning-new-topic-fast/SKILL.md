# Rapid Learning Procedure

## Trigger / when to use
Load when you need working competence in a new area quickly — a new language, framework, domain, or tool — and "take a 6-week course" is not an option.

## Approach
1. **Define "working competence" concretely**: what will you be able to DO when you're done? "Build a small X" beats "learn X". The project is the curriculum.
2. **Steal the syllabus**: find the best 3 resources (one book/course, one reference, one community) and ignore the rest. Depth in three beats breadth in thirty.
3. **Learn by building immediately**: start the project on day one, and learn each concept at the moment the project needs it. Just-in-time learning sticks; just-in-time doesn't.
4. **Use the Feynman technique**: explain each new concept in plain words as if teaching a beginner. Where the explanation breaks, your understanding breaks — go back.
5. **Deliberate the hard parts**: identify the 20% of sub-skills that cause 80% of the difficulty and drill them with focused repetition, not re-reading.

## Pitfalls
- Tutorial hell — following along without building anything of your own.
- Collecting resources (bookmark hoarding) as a substitute for learning.
- Skipping fundamentals that later become load-bearing.

## Verification
You can build the target project without a tutorial open; you can explain the core concepts to a beginner; you can debug your own mistakes using the official reference.
Check yourself by closing all tutorials and building the target project from a blank file.
