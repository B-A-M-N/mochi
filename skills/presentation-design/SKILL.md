# Presentation Design Procedure

## Trigger / when to use
Load when preparing any presentation: a conference talk, a team demo, a pitch, or a status review that must persuade or inform a specific audience.

## Approach
1. **One sentence the audience should remember**: if the whole talk fits in one sentence, the deck has a spine. Build every slide to serve that sentence.
2. **Narrative arc over feature list**: context (why this matters) → tension (the problem) → resolution (your approach) → proof (demo/evidence) → ask (what you want). Feature tours lose audiences; arcs don't
3. **One idea per slide**: a slide with three points is three slides. Big type, one visual, minimal bullets. If you need speaker notes, put them in notes — not on the slide.
4. **Design for the back row**: minimum ~24pt body text, high contrast, no walls of code. Code demos get one zoomed snippet, not a file dump.
5. **Rehearse the transitions**: the handoff between slides is where talks die. Practice the first 60 seconds and the demo path until they are boring.

## Pitfalls
- Reading slides aloud — the audience can read faster than you speak.
- Demos without a backup (screenshot/video) when the network or environment fails.
- Ending with "any questions?" with no ask and no next step.

## Verification
A stranger can state the one-sentence takeaway after a single read of the title slide; every slide passes the "one idea" test; the demo has a recorded fallback.
